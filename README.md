# PPI Global Radar

Единый инструмент автоматизированного мониторинга новостей целлюлозно-бумажной
промышленности и упаковки по странам БРИКС+ — от сбора до публикации в
Telegram-канал. Управляется через веб-интерфейс (Streamlit) или командную строку.

## Быстрый старт

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
cp .env.example .env   # заполните токены и ключи — см. разделы ниже
streamlit run app.py
```

Откроется `http://localhost:8501`. Дальше — по вкладкам слева направо:
Обзор → Сбор → Фильтр → Редактура → Картинки → Карточки и публикация →
Источники → Настройки.

## Как это работает — сквозной поток данных

```
RSS (официальные + автонайденные) ──┐
                                      ├─→ единый формат → тематический фильтр (ключевые слова/дедуп)
headless (несколько парсеров) ────────┘         (data/filtered.json)
                                             │
                                             ▼
                          LLM: скоринг важности + перевод + комментарии мир/Россия
                                     (data/scored.json)
                                             │
                                             ▼
                  автоотбор в дайджест (можно вручную переопределить чек-листом)
                          (data/digest_cards.json, data/candidates_by_country.json)
                                             │
                                             ▼
                          og:image (если есть у источника)
                                             │
                                             ▼
                      сборка HTML-карточек Telegram (data/tg_cards/)
                                             │
                                             ▼
                         публикация (только после явного подтверждения)
```

Все промежуточные файлы лежат в `data/` и перезаписываются на каждом прогоне
соответствующего шага — истории прошлых выпусков пока нет.

## Настройка Telegram с нуля

1. **Создайте канал**: "Новый канал" → тип "Публичный" → юзернейм, например
   `PPIGlobalRadar` (ссылка `t.me/PPIGlobalRadar`).
2. **Создайте бота**: [@BotFather](https://t.me/BotFather) → `/newbot` → сохраните токен.
3. **Добавьте бота администратором канала** с правом "Публикация сообщений" —
   без этого шага отправка не будет работать в принципе.
4. В `.env`:
   ```
   TELEGRAM_BOT_TOKEN=<токен от BotFather>
   TELEGRAM_CHAT_ID=@PPIGlobalRadar
   ```
   Для публичного канала `@username` полностью заменяет числовой ID. Для
   приватного канала нужен числовой ID (`-100...`) — узнать через
   [@userinfobot](https://t.me/userinfobot) или `getUpdates` API.

## LLM для редакторского шага (скоринг, перевод, комментарии)

Раньше это делалось вручную (редактором-человеком). Теперь автоматизировано
через выбираемую цепочку провайдеров с автопереключением — если у одного
кончился лимит, редактор сам пробует следующего.

**Настройка в веб-интерфейсе:** вкладка «⚙️ Настройки» → блок "Автопереключение"
→ задайте порядок приоритета (1-й, 2-й, 3-й...) → впишите ключи ниже →
"💾 Сохранить настройки" (применяется сразу, без перезапуска).

Провайдеры:

| Провайдер | Стоимость | Как получить ключ | Примечание |
|---|---|---|---|
| **Groq** | Бесплатно | https://console.groq.com/keys | Быстрый, щедрый лимит. Рекомендуется первым в цепочке. |
| **OpenRouter** | Бесплатно | https://openrouter.ai/keys (карта не нужна) | Модель по умолчанию `openai/gpt-oss-120b:free`. Каталог бесплатных моделей часто меняется — актуальный список: https://openrouter.ai/models?max_price=0. Лимит скромный (~20 запросов/мин, ~200/день) — держите вторым-третьим в цепочке. |
| **Gemini** | Бесплатно, но **ненадёжно доступен из России** | https://aistudio.google.com/apikey | Из-за экспортных ограничений США запросы с российских IP могут получать 429 даже при пустой квоте на странице. Если вы в России — не ставьте Gemini в цепочку, толку не будет. |
| **Ollama** | Бесплатно, локально | https://ollama.com → `ollama pull llama3.1` | Без лимитов запросов, но ест ресурсы вашей машины. Нужен запущенный `ollama serve`. |
| **Anthropic (Claude)** | Платно | https://console.anthropic.com/ | Оставлен как опция, если важно качество и не критична стоимость. |

**Рекомендованная цепочка из России:** `groq → openrouter` (Gemini и,
возможно, некоторые другие западные API могут быть геоблокированы
независимо от настроек в этом проекте — это ограничение на стороне
провайдера, не баг кода).

Без ни одного настроенного провайдера редактор использует грубую эвристику
вместо реальной оценки и явно предупреждает об этом в интерфейсе.

## Структура

```
ppi_radar/
  config.py                — пути, .env, константы, LLM_PROVIDER_CHAIN
  country_map.py            — нормализация названий стран (EN база → RU пайплайн)
  source_priority.py         — приоритет A/B/C/NO для каскадного отбора
  editorial_log.py            — журнал решений (approve/reject) для будущего PPI Yield
  archive.py                   — накопительный архив всех собранных новостей
  sources.py                    — работа с базой источников (CSV v9)
  vendor/
    ppi_html_adapters/           — вендоренный пакет: 21 HTML-адаптер для источников
                                    без RSS/API (Segezha, Klabin, FT, Caixin и др.),
                                    включая 3 китайских уровня A/B. Установки не
                                    требует — работает сразу после распаковки проекта.
                                    См. vendor/README.md, если придёт обновление пакета.
  collectors/
    rss.py                    — сбор по RSS + диагностика по каждому источнику
    headless_news.py           — headless/API-парсеры (Китай, Индия, Египет, Эфиопия, Индонезия)
    html_adapters.py            — обёртка над vendor/ppi_html_adapters
    discover_rss.py             — автопоиск новых RSS-фидов среди непроверенных источников
    tradestat.py                 — торговая статистика Индии (отдельно, для аналитики)
  processing/
    filter.py                   — тематический фильтр + дедупликация + диагностика воронки
    editor.py                    — LLM-скоринг/перевод/отбор дайджеста + каскад A→B→C
    llm_providers.py              — единый клиент с автопереключением между провайдерами
    images.py                     — og:image → twitter:image
  publishing/
    cards.py                      — сборка HTML-карточек Telegram
    telegram.py                    — реальная отправка (с премодерацией)
  pipeline.py                     — CLI, всё вместе
app.py                            — веб-интерфейс (Streamlit) — основной способ работы
sources/                          — CSV база источников + автонайденные RSS + приоритеты
data/                              — рабочие файлы (создаются автоматически)
```

## Веб-интерфейс — по вкладкам

- **📊 Обзор** — сводка по базе источников (сколько рабочих/непроверенных),
  статус каждого этапа пайплайна.
- **🌐 Сбор** — запуск RSS и headless-сбора, таблица диагностики по каждому
  источнику (сколько отдал, есть ли ошибки) — так виден каждый нерабочий
  источник, а не только итоговая цифра.
- **🔎 Фильтр** — воронка отсева с разбивкой по причинам (вне окна свежести /
  не по теме / дубли) и по каждому источнику отдельно.
- **🤖 Редактура** — запуск LLM-скоринга, слайдеры глубины отбора (новостей на
  страну / мировых новостей), и главное — чек-лист "Почему выбраны именно эти
  новости": можно включить/исключить ЛЮБОГО кандидата из всего отфильтрованного
  пула (не только замена внутри своей страны), не отходя от этой вкладки.
- **🖼️ Картинки** — поиск og:image для отобранных карточек.
- **📰 Карточки и публикация** — точечное редактирование текста карточек,
  индивидуальный чекбокс включения в публикацию, предпросмотр, и сама
  публикация — защищена обязательным подтверждающим чекбоксом.
- **🔬 Источники** — автопоиск новых рабочих RSS-фидов среди непроверенных
  источников базы (через стандартный механизм `<link rel="alternate">`,
  с обязательной валидацией — фид засчитывается, только если реально
  парсится и содержит записи).
- **⚙️ Настройки** — Telegram, цепочка LLM-провайдеров, база источников.

## Командная строка (альтернатива веб-интерфейсу)

```bash
python -m ppi_radar.pipeline status              # сводка по базе источников
python -m ppi_radar.pipeline collect              # сбор RSS + headless
python -m ppi_radar.pipeline filter               # тематический фильтр
python -m ppi_radar.pipeline edit --per-country 2 --max-world 3   # скоринг + отбор
python -m ppi_radar.pipeline images                # og:image
python -m ppi_radar.pipeline cards --date 19.07.2026
python -m ppi_radar.pipeline publish               # dry-run — посмотреть, что уйдёт
python -m ppi_radar.pipeline publish --publish      # реально отправить
python -m ppi_radar.pipeline all                    # весь цикл разом (dry-run по умолчанию)
```

Чек-лист ручного отбора (по стране/по миру) доступен только в веб-интерфейсе —
через CLI работает только автоматический отбор по `per_country`/`max_world`.

## Cron (ежедневно в 8:00, без автопубликации)

```
0 8 * * * cd /path/to/ppi_radar && /usr/bin/python3 -m ppi_radar.pipeline all >> logs/daily.log 2>&1
```

`--publish` в cron **намеренно не ставится** — премодерация остаётся ручным
шагом: посмотрите `data/tg_cards/`, и если всё устраивает, запустите
`python -m ppi_radar.pipeline publish --publish` вручную (или через веб-интерфейс).

## Аналитика (отдельно от новостного дайджеста)

`ppi_radar/collectors/tradestat.py` — торговая статистика Индии по главам
47/48/49 (целлюлоза/бумага/печатная продукция), включая билатераль по БРИКС+.
Не входит в `pipeline all`:
```bash
python -m ppi_radar.collectors.tradestat
```
Результат — `data/tradestat_results.json`, сырьё для страновых профилей,
товарной аналитики и дашборда торговых потоков.

## Известные ограничения

- **Охват источников узкий по конструкции**: только технически проверенные
  источники из официальной базы v9 плюс автонайденные/импортированные RSS
  (вкладка «🔬 Источники» подмешивает их автоматически) — не весь интернет,
  это не похоже на поиск в духе Perplexity, зато полностью прозрачно и
  воспроизводимо: видно, откуда что берётся и почему отсеивается. **Точные
  текущие цифры** (сколько рабочих, сколько требуют доразведки, сколько
  автонайдено) — на вкладке «📊 Обзор», они меняются по мере добавления
  источников, поэтому здесь намеренно не фиксируются.
- **Источники без RSS** (HTML-страницы, статус `DISCOVERY_REQUIRED` в базе)
  требуют ручной разведки — у каждого сайта своя вёрстка/защита, это
  принципиально не автоматизируется вслепую. Список с причинами и
  приоритетом — на вкладке «🔬 Источники».
- **Даты у некоторых headless-источников** не парсятся надёжно (относительные
  форматы на местных языках) — такие записи по умолчанию считаются
  "свежими", фактическую проверку берёт на себя LLM на этапе редактуры.
- **Бесплатные LLM-провайдеры имеют лимиты** — при росте объёма собираемых
  новостей рано или поздно в них упрётесь. Цепочка автопереключения смягчает
  проблему, но не устраняет её полностью.
- **Gemini ненадёжен из России** — см. таблицу провайдеров выше.
- **История дайджестов не хранится** — каждый прогон перезаписывает
  предыдущий результат в `data/`.
- **Открытый вопрос по TRADESTAT**: что именно Россия экспортирует в Индию по
  HS 4907 (книги vs ценные бумаги/бланки) — нужна точечная детализация.
